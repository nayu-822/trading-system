# 自動売買システム仕様書（ローカルPC運用）

---

## 1. 概要

本システムは、Windows ローカルPC 上で稼働する以下の 3 プロジェクトで構成される。

1. 自動売買システム（trading-engine）
2. 通知システム（notification-service）
3. GUI 分析ツール（gui-tool）

それぞれは疎結合に設計し、独立して開発・運用可能とする。

自動売買は三菱UFJ eスマート証券の `kabuステーション API` を利用する想定とし、`kabuステーション` を起動した Windows ローカルPC から売買リクエストを行う。

---

## 2. 全体構成

[Windows ローカルPC]
- trading-engine（自動売買）
- notification-service（Discord 通知）
- gui-tool（可視化・分析）
- kabuステーション（証券会社 API クライアント）

---

## 3. プロジェクト構成

### 3.1 trading-engine

#### 目的
- 売買ロジックの実行
- 発注処理の抽象化
- ログ保存
- バックテスト
- パラメータ最適化

#### 機能要件
- Windows 上で動作する
- `kabuステーション` 起動中のローカルPCから API を呼び出す
- 日本株市場の取引可能時間のみ稼働する
- トレンド戦略とレンジ戦略の両方に対応する
- paper / live の切替が可能である
- 取引ログとシステムログを分離して保存する
- バックテストと本番売買コードを分離する
- 最適化処理はオフライン実行とする

#### 主な内部構成
- `data`：市場データ取得
- `strategies`：シグナル生成
- `execution`：発注実行、paper / live の切替
- `core`：通常売買フローのオーケストレーション
- `backtest`：バックテスト実行
- `optimization`：パラメータ最適化
- `logging`：取引ログ永続化

### 3.2 notification-service

#### 目的
- Discord への通知送信
- 売買処理と完全に分離した非同期通知

#### 機能要件
- Discord Webhook による通知送信
- Queue / 非同期 I/O による非同期実行
- 売買処理の成功・失敗に依存しない構成

### 3.3 gui-tool

#### 目的
- ログの可視化
- パフォーマンス分析
- バックテスト結果の比較閲覧

#### 技術スタック
- Nuxt
- TypeScript
- ローカル Web UI
- Node.js は Volta でバージョン固定する

#### 機能要件
- CSV / SQLite の読み込み
- 損益推移表示
- 日次・月次集計
- 戦略別比較表示
- フィルタリング（銘柄・期間・戦略）

---

## 4. 外部 API

- 三菱UFJ eスマート証券 `kabuステーション API` を利用する
- `kabuステーション` は Windows ローカルPC 上で起動していることを前提とする
- 実売買時は API 接続状態を事前に確認する

---

## 5. モード切替

- `paper`：擬似約定による検証モード
- `live`：実売買モード
- モードは設定ファイルで切り替える

---

## 6. 非同期設計

- 売買処理と通知処理は完全に分離する
- 通知は Queue 経由で送信する
- 売買処理は通知成功 / 失敗に依存しない

---

## 7. スケジューリング

- Windows タスクスケジューラ等により制御する
- 日本株市場の取引時間のみ起動する
- 市場時間制御は共通モジュールで管理する

## 9. 戦略

### 9.1 トレンド戦略（trend）
- 移動平均クロスを基本とする
- シグナルのみを返す
- 発注処理は行わない

### 9.2 レンジ戦略（range）
- RSI を基本とする逆張り戦略とする
- `lower_threshold` 未満で buy
- `upper_threshold` 超過で sell
- それ以外は hold
- シグナルのみを返す

## 10. バックテスト機能

### 概要
本システムは、過去データを用いて売買ロジックの性能を検証するためのバックテスト機能を提供する。戦略の評価・比較・最適化を目的とする。

### 対応戦略
- トレンド戦略（trend）
- レンジ戦略（range）

### 実行方法
#### 単体バックテスト
- 指定した戦略でバックテストを実行する

#### 比較モード
- `--compare` 指定時
- trend と range を同一条件で同時実行する

#### 最適化モード
- `--optimize` 指定時
- パラメータの組み合わせを探索する
- 最良結果を出力する

### 評価指標
バックテスト結果として以下を出力する。

- total_trades（総取引数）
- total_pnl（総損益）
- average_pnl（平均損益）
- win_rate（勝率）
- max_win_streak（最大連勝数）
- max_loss_streak（最大連敗数）
- max_drawdown（最大ドローダウン）

### 比較機能
複数戦略の結果を同時に出力する。

対象：
- trend
- range

同一条件：
- 同一銘柄
- 同一期間
- 同一データ
- 同一数量

### パラメータ最適化
グリッドサーチにより、最適なパラメータを探索する。

対象例：
- RSI 期間
- 下限閾値
- 上限閾値

評価基準：
- total_pnl 最大化

### データソース
バックテストは以下のデータを使用する。

- yfinance（外部 API）
- CSV（将来対応）

データ形式：
- timestamp
- open
- high
- low
- close
- volume
- symbol

### 制約
- 単一ポジション前提
- 逐次処理（look-ahead bias 回避）
- 戦略ロジックは独立
- 売買ロジックと通知は分離

### 拡張性
将来的に以下に対応可能とする。

- 複数銘柄同時バックテスト
- walk-forward 検証
- 並列最適化
- GUI 連携

---

## 11. 拡張性

- 戦略の追加が容易であること
- executor の差し替えで他証券 API に対応可能であること
- データソース追加（yfinance / CSV / 将来の DB）に対応可能であること
- GUI 連携による結果可視化を行えること

---

## 12. 非機能要件

- 高可用性
- 障害時の影響最小化
- ログ完全保存
- 長時間安定稼働
- `kabuステーション` 未起動時は安全に停止またはエラー化する
